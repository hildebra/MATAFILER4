MGS audit — 11 September 2026

The original audit reported 12 findings in the non-strain workflow. After the requested follow-up, **three are fixed, one is accepted behavior, and eight remain open** (four P1 and four P2). The follow-up fixes only gzip close failures, Canopy cache validation, and abundance job CPU allocation. Existing between-MGS trees remain usable for outgroup finding, including preliminary lower-resolution trees while the final phylogeny runs for several weeks. Biological filtering thresholds are unchanged.

`strain_within.pl` and its downstream-only functions and scripts are excluded, as requested. The MGS-side launcher arguments remain in scope. Other work was modifying shared modules during this audit; the references and final test results below describe the workspace after the consolidation. Changes made by those other tasks were not reverted or included as this audit's fixes.

**Findings and follow-up status**

Historical reproduction commands below used the then-supported `-redoCluster 1`. That option is now removed; its replacement is `-redo cluster`. `-redoTax 1` is replaced by `-redo tax`. The consolidated choices are `none`, `cluster`, `tax`, `tree`, `input`, and `all`. `tree` and `input` retain their strain-workflow scope; `all` now also rebuilds clustering and taxonomy/abundance. See the [flag reference](flag_reference.md#mgspl).

1. **[P1] A dry run deletes existing products and runs clustering.**

   [MGS.pl](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS.pl:469) removes cluster products and invokes derivative invalidation without checking `doSubmit`; [the clustering call](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS.pl:575) executes `systemW` unconditionally. The flag is documented as `0: dry run`. Running the actual controller with `-submit 0 -redoCluster 1`, a temporary catalog, and a recording cluster executable returned success after executing the binary and deleting both the old core table and a saved between-MGS result. The submit flag currently guards scheduler submission, not the whole workflow. Gate destructive actions and direct computations before preparing a dry-run plan.

2. **[P1] Two controllers can mutate the same output directory concurrently.**

   The only [workflow lock acquisition](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS.pl:422) is scoped to the derivative-invalidation closure. It is released before clustering or annotation; there is no MGS-controller lock. Two actual controllers launched against the same temporary output directory both reached a barrier inside the clustering executable and both exited zero. They can race on the shared cluster files, logs, genome deletion/extraction and checkpoints. Hold a lock for the controller's entire mutation lifetime, and account for already submitted child jobs before allowing a replacement run to remove their inputs.

3. **[P1] Reclustering retains Kraken taxonomy for the previous MGS identities.**

   [The Kraken scheduling predicate](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS.pl:804) tests only whether two files are nonempty. Cluster invalidation removes the other checkpoints but leaves these files. [taxPerMGS.pl](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS/taxPerMGS.pl:20) repeats the same early return. A worker reproduction first annotated 100 genes as MGS.1, then changed the guide to MGS.2; the second invocation exited zero while its LCA output still named MGS.1. Changed Kraken annotations have the same problem. Bind these products to the guide and Kraken input, and invalidate or explicitly rebuild them with clustering.

4. **[P1] The new abundance worker does not preserve small-sample MGS results.**

   [annotateMGwSpecIs3.pl](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/GC/annotateMGwSpecIs3.pl:33) fixes `minGuideNonzero` at three and passes it to cc.bin. The actual bundled binary rejects a one-sample abundance matrix. With ten clean MGS seed genes across ten distinct COGs, it succeeds on two samples but produces zero assignments and only the background row; the equivalent three-sample fixture produces all ten assignments and the MGS abundance row. MGS.pl permits these small catalogs and merely skips the between-MGS tree when necessary. A small-sample abundance route must preserve directly supported MGS assignments without relying on unsupported profile correlation; silently emitting no MGS rows is not a valid substitute.

5. **[P2] The Perl clustering compatibility output cannot be consumed by the rest of the pipeline.**

   [summarizeMAGcontent](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS/clusterMAGs.pl:889) emits six metadata columns before marker categories, whereas [markersPerMGS.pl](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS/markersPerMGS.pl:66) requires `Contamination` at column eight and assumes 22 metadata columns. Passing the producer's header to the actual consumer immediately fails with `Not correct header`. The producer also uses `sample.bin` IDs while contig extraction expects `sample__bin`. Consequently `-perlClusterMAGs` is not a working end-to-end compatibility mode even when clustering succeeds. Use one explicit report schema and identifier convention for both engines and their consumers.

6. **[P2] Unassigned MAGs become representative genomes for an MGS named “?”.**

   [getRepresentBins](/mnt/c/users/hildebra/documents/locdev/matafiler4/Mods/Binning.pm:370) accepts every second-column value, including `?`, and selects a default representative even without a star. A canonical two-row report containing one assigned MAG and one unassigned MAG returns both `MGS.1 => S1__binA` and `? => S1__binB`. createBinCtgs then treats both as genome outputs. The family variant has the same missing membership exclusion. Reject unassigned rows and restrict extraction to the retained core MGS set so discarded groups cannot survive as exported genomes.

7. **[Fixed, formerly P2] Report readers ignored gzip close failures.**

   Both representative-bin readers in [Binning.pm](/mnt/c/users/hildebra/documents/locdev/matafiler4/Mods/Binning.pm:380) and [markersPerMGS.pl](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS/markersPerMGS.pl:90) now check the input close status and fail with the report path and reader status before returning parsed data or publishing derivatives. Regression fixtures remove the gzip trailer while retaining every readable row; both representative readers fail, and the marker worker preserves an existing completed output.

8. **[Fixed, formerly P2] Canopy filtering and QC could reuse stale inputs.**

   [CanopyPrep](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS.pl:1444) now uses the existing `Mods::Checkpoint` manifest helper. Its contract includes source and protein-catalog paths, the 700-gene threshold, the selected quality-checker command, and the configured CheckM2 database. The manifest records source/protein input and filtered/QC output sizes and modification times. Old results without a valid manifest are rebuilt; `-redo cluster` and `-redo all` force a rebuild even when the manifest matches. This deliberately uses the shared metadata fingerprints rather than hashing the complete protein catalog.

   Before QC, stale `.faa` Canopy bins are removed so dropped groups cannot survive in the quality-checker input directory. The filtered table is published by the existing rename helper, and the manifest is written only after successful QC. Zero-Canopy results are checkpointed without running QC. CheckM1 and CheckM2 now share one submission/wait path with their existing respective resources. Tests cover legacy-cache rebuilding, unchanged reuse, source/protein/checker changes, missing/damaged outputs, explicit redo, failure recovery, and zero-Canopy reuse.

9. **[Accepted behavior] Reuse an available between-MGS tree before final phylogeny completion.**

   The user confirmed that the final phylogeny can take several weeks and that a lower-resolution initial tree is sufficient for outgroup finding. The existing [tree reuse decision](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS.pl:663) is therefore preserved; no final IQ-TREE completion or BuildTree policy checks were added to this route. An explicit clustering rebuild still invalidates its dependent tree as before. The worker's older internal policy predicate was observed during the original audit, but changing it is outside the approved fixes.

10. **[P2] Annotation checkpoints omit biological inputs that the workers actually consume.**

    [The input fingerprint list](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS.pl:328) records the full matrix, catalog FASTAs, maps and optional Canopy input. It omits the marker-specific matrix, marker category table and marker LCA files used by the abundance workers. The [GTDB stage contract](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS.pl:1161) also omits the configured taxonomy database/tool release. Replacing one of those inputs can leave the current checkpoints valid, so a normal resume returns the previous annotation. Fingerprint each stage's direct semantic inputs, with a deliberate compatibility policy for old manifests; there is no need to hash the complete catalog on every invocation.

11. **[Fixed, formerly P2] Abundance worker threads exceeded the scheduler CPU request.**

    [MGS.pl](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/MGS.pl:851) now reserves `$canCore` CPUs for the MGS/specI abundance job, matching the worker's `-cores` argument. The 64G total-memory request is unchanged. A regression runs the actual command-building/submission block with a recording scheduler substitute and verifies both worker threads and allocated CPUs at a nondefault value of seven.

12. **[P2] Binner-local abundance runs still overwrite a catalog-global assignment file.**

    [annotateMGwSpecIs3.pl](/mnt/c/users/hildebra/documents/locdev/matafiler4/secScripts/GC/annotateMGwSpecIs3.pl:189) always publishes final assignments to `$GCd/<marker>/gene2specI.txt`, even when MGS.pl provides a separate binner-local output directory. importSpeciAssignments opens this path with truncation. Running a second binner or repeating annotation without MGS can overwrite the first run's catalog assignment map; simultaneous runs can race it. This file is also consumed by the independent FMGgenes2tree workflow. Keep run-specific assignments with the other annotation outputs and update consumers to select the correct generation explicitly.

**Original consolidation implemented**

- Extracted the two map-copy/filter loops into [CatalogPaths::filter_catalog_maps](/mnt/c/users/hildebra/documents/locdev/matafiler4/Mods/CatalogPaths.pm:201), used by MGS.pl and the clustering wrapper. It retains source order, map metadata and empty headers, and reuses the original specification when no exclusions apply.
- Both callers now publish complete filtered files by rename, preserve the existing destination when publication fails, and clean a failed temporary output. This replaces the wrapper's direct output truncation and MGS's unlink-before-rename gap.
- Removed the unconditionally disabled per-assembly binning loop, its empty job waits, the disabled old abundance branch, two uncalled legacy conversion helpers, and imports/configuration lookups used only by those blocks. This does not enable or alter binning: it was already unreachable.
- Added 12 behavior checks to the existing catalog-path suite. Production-code changes total 52 added and 192 removed lines, for a net reduction of 140 lines. The test additions are separate.

**Follow-up verification**

The scoped suite passes **21 test files / 892 assertions**, including 52 new behavior checks in [mgs_controller_fixes.t](/mnt/c/users/hildebra/documents/locdev/matafiler4/t/mgs_controller_fixes.t) and [mgs_report_integrity.t](/mnt/c/users/hildebra/documents/locdev/matafiler4/t/mgs_report_integrity.t). The tests execute the controller's actual option setup, Canopy helper, and abundance submission block with substituted site configuration and scheduler/QC tools. They use the real protein extraction and checkpoint helpers; the gzip fixtures invoke a real decompressor. Command-line help and documentation coverage pass. MGS.pl, Binning.pm, and markersPerMGS.pl pass syntax checks. The scoped test log is [available locally](/tmp/mgs-fixes-regressions.log).

The original consolidation passed 18 files / 773 assertions. Its first broad test invocation started before the strain exclusion arrived and included strain tests being edited by another task; those failures were not findings in this audit. No changes were made to strain_within.pl. One existing test of MGS.pl's downstream arguments was updated to recognize the consolidated option name and choices.

The original audit used temporary controller, concurrency, annotation, cache, and native-binary probes. Controller probes substituted site configuration and expensive executables; abundance probes invoked the bundled cc.bin. The local-backend launcher probe exposed a numeric-job-ID assumption after synchronous success, but it was not counted among the original findings because the production entry points did not expose a way to select that backend. Real scheduler/QC runs, GTDB databases, and full production catalogs remain untested.

Existing documentation already records some of the cache, dry-run and shared-sidecar concerns. This report confirms their state and adds specific reproductions; it does not claim they were all introduced recently. Stage-I assignment reuse after a checkpoint mismatch remains an explicit, warned recovery policy and was not tightened during this work.
